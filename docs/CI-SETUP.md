# GitHub setup and validation boundaries

Target: public `Framed-AI-Ltd/Plumb`, maintainer `Dev-Addict`. Setup is an explicit administrator action. Verify current server-side settings rather than inferring protection from workflow files.

After creating the public repository, pushing reviewed signed initial source and creating main/develop, an authorized organization administrator runs `node tools/configure-repository.mjs --apply` using their existing gh session. The script refuses other identities/visibility, configures and reads back secret scanning/push protection, Dependabot alerts/fixes, signed-commit rulesets, required checks/reviews, merge queues, protected tags, npm environment and Pages. Inspect `review-setup/github-readback.json`. Failures are fatal; no unsupported API is silently treated as success. Organization policy or plan restrictions may require an admin change. [Rulesets API](https://docs.github.com/en/rest/repos/rules), [repository API](https://docs.github.com/en/rest/repos/repos), [environments API](https://docs.github.com/en/rest/deployments/environments).

The API-backed Codex review workflow is retained but disabled on GitHub. Native automatic review is configured in your ChatGPT account and requires no API key. If explicitly reenabling the optional API workflow, set the GitHub Actions secret `OPENAI_API_KEY`. Optionally set `OPENAI_REVIEW_MODEL` to an API model available to your account; leaving it unset uses the Codex CLI default. Anthropic credentials are no longer used. The official `openai/codex-action` is pinned to its v1 commit, with CLI 0.165.0 (older than the three-day minimum), high effort, a read-only permission profile and dropped sudo privileges. No provider key belongs in developer files.

Automatic Codex reviews run for non-draft PRs into protected `main`/`develop` whose author GitHub identifies as an organization member (`MEMBER`), including members working from forks. Outside collaborators and other external authors do not trigger automatic reviews. To authorize a one-off review of any open, non-draft PR, an organization member posts exactly `/codex-review` as a new PR conversation comment. This also reruns a member PR. Nonmembers cannot authorize it. Each command authorizes the current immutable PR revision only; new outside-author pushes require a new command. Edits to old comments, labels, issue comments outside PRs, and commands embedded in other text do not trigger reviews. The comment workflow must first exist on the default branch.

One Codex review covers bug finding, security, performance and maintainability/idiomatic code. It receives a trusted prompt, PR diff and immutable Git objects for surrounding context; PR files are never checked out, and PR code/tests/install scripts are not executed. Findings appear in a commit-specific PR comment, workflow summary and retained artifact. Malformed results or high/critical findings fail the workflow. Human review remains required. This is not a second independent model-family review.

The gate and helpers load explicitly from the default branch, then subsequent jobs use that resolved trusted SHA. `github.sha` on `pull_request_target` can refer to the PR base branch and must not substitute for the trusted default branch. The workflow runs only from protected Gitflow integration branches; activate and verify their protections before enabling provider secrets. PR and comment metadata are revalidated through GitHub before spending provider credentials. Results are not posted if the PR head/base has changed. The reviewer has read-only GitHub permissions; the separate reporting job alone receives PR-comment write access. No wildcard actor allow-list is used. Membership uses GitHub's server-provided association, not repository write permission, and requires no organization-membership secret.

CI still runs browser/calendar, accessibility, screenshot, dependency, Semgrep and workflow-security checks separately. The `pull_request_target` dangerous-trigger audit exception is limited to this member-gated workflow, which reads PR objects as untrusted data. All other workflow findings remain fatal. Secret scanning/push protection is server-side and requires the setup readback above. See the [official action](https://github.com/openai/codex-action) and [GitHub event semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request_target).

PR CI always runs static/unit checks, the packed-consumer smoke and security checks. The required accessibility job runs for UI-affecting changes. Story-only changes select their owned stories from Storybook's built inventory; shared source, styles, compiler configuration, dependencies, package identity, missing history and unknown paths conservatively select all stories. Documentation-only changes skip the browser job rather than leaving a required workflow pending. Selection runs inside the required check job, so a classifier failure cannot silently bypass it.

One Storybook build supplies mobile/desktop, light/dark captures (360/1440 px). The same pass checks rendering, console errors, sideways overflow, desktop axe and critical mobile accessibility. Browser and calendar regressions remain blocking. Pixel differences are advisory evidence in the review artifact, compared with the committed references; they do not grant owner visual approval. The duplicate base/head PR workflow is removed.

Render jobs use Ubuntu 24.04, lockfile-pinned Chromium, bundled fonts, fixed locale/time zone/date, reduced motion and device scale 1. Existing references were owner-inspected separately; cross-platform single-pixel differences are not treated as application failures. Local `pnpm test:visual` retains strict comparisons against those unchanged references. New baselines still require inspection and explicit owner approval before committing.

Full visual review runs nightly and by workflow dispatch, with all stories at 360/768/1440 px in both themes, same-environment base/head evidence and the complete responsive-template review. Run it manually with main as both base and head before release and inspect its artifacts. These scheduled/manual triggers become available once the updated workflow reaches the default branch. Full review detects rendering/accessibility failures; screenshot differences remain review evidence, not automatic approval.

After setup, run a disposable PR through develop's queue and verify the synthetic merge-group checks, a rejected unsigned/force push, missing-provider failure, npm environment gate and Pages paths. Those live checks remain unrun. Provider reports may contain source text; artifact retention is 14 days. Never include secrets in a patch.

Required branch checks are `check`, `accessibility`, `workflow-security`, `static-rules`, and `dependency-review`. Codex review runs automatically for organization-member PRs and on explicit member authorization for other PRs. It remains advisory to merge protection; owners must inspect the reviewed-head report. Outsider PRs retain static CI and human review without an automatic provider review.

The approved solo-maintainer policy requires no external approval on main/develop PRs. Required CI, signed commits, resolved review threads, merge queues, deletion protection and force-push protection remain enforced. Release/hotfix branches retain their approval requirements. `pnpm repo:configure --apply` preserves this policy; regression tests cover its review settings.


Release verification and packing run without npm OIDC permission. The environment-gated publisher downloads the same run’s tarball, checks that exactly one archive exists, and publishes with lifecycle scripts disabled. It does not check out or execute project source.
